#### How to verify A5 + A5b (manual smoke, ~3 min)

Telemetry is silent — there's no UI surface inside PC2 itself. Three places to look:

**1. Live counts via the public summary endpoint (no auth needed)**

```bash
curl -s http://localhost:4200/api/telemetry/onramp/summary | jq
```

Expected shape (after a fresh boot + login + opening any non-explorer app):

```json
{
  "events": {
    "install_started": 1,
    "wallet_ready": 1,
    "first_capsule_open": 1,
    "first_payment": 0
  },
  "unique_installs": 1,
  "first_ts": "2026-04-25T...",
  "last_ts": "2026-04-25T..."
}
```

Each event count caps at 1 per install (idempotent via `settings.telemetry_<event>_at`). Counts grow only when **new** users on **other** PC2 nodes complete the same step.

**2. Visual dashboard (open in any browser)**

```bash
open deploy/dash/onramp.html
# Or with a custom API origin:
open "deploy/dash/onramp.html?api=http://localhost:4200&refresh=5"
```

Self-contained HTML — no server required. 4 funnel cards + bar chart, auto-polls every 10s by default. The same file `scp`'d to a supernode static dir becomes the public dashboard at e.g. `dash.ela.city/onramp`.

**3. Direct DB read (proves the data is on disk)**

```bash
sqlite3 pc2-node/data/pc2.db "SELECT event, ts, install_id FROM telemetry_onramp ORDER BY ts;"
sqlite3 pc2-node/data/pc2.db "SELECT key, value FROM settings WHERE key LIKE 'telemetry%';"
```

The `install_id` is your anonymous UUID (one row in `settings`); each event row references it.

**Privacy kill switch (verify it works):**

```bash
PC2_TELEMETRY_DISABLED=true npm --prefix pc2-node run start
# Then re-trigger any flow — POST /api/telemetry/onramp returns 204 with {"disabled":true}
# and zero rows are inserted. GET /summary still works (returns existing counts).
```

**To re-trigger events for testing** (since each fires only once per install):

```bash
sqlite3 pc2-node/data/pc2.db "DELETE FROM telemetry_onramp; DELETE FROM settings WHERE key LIKE 'telemetry_%_at';"
# install_id row is preserved so identity stays stable across re-tests.
```

Then restart the node (fires `install_started`), log out/in (fires `wallet_ready`), open any capsule from the start menu (fires `first_capsule_open`).

## How to verify A5 + A5b (manual smoke)

The dashboard is wired up but invisible to the user under normal operation — it lives at a static HTML file you load yourself, NOT as a default UI surface in the desktop. Here's what you can poke at to see it working:

### 1. View the live funnel JSON (zero setup)
```bash
curl -s http://localhost:4200/api/telemetry/onramp/summary | jq
```
Expected: `events` object with 4 counters (`install_started`, `wallet_ready`, `first_capsule_open`, `first_payment`), `unique_installs`, `first_ts`, `last_ts`. After your real boot today `install_started` should be `1`.

### 2. Open the visual dashboard
Open `deploy/dash/onramp.html` in any browser **with the query string `?api=http://localhost:4200`** appended:
```
file:///<repo>/deploy/dash/onramp.html?api=http://localhost:4200&refresh=5
```
Expected: 4 funnel cards + a bar chart auto-refreshing every 5s.

### 3. Trigger each event live
- **install_started** — already fired on boot today; clear with `sqlite3 pc2-node/data/pc2.db "DELETE FROM telemetry_onramp; DELETE FROM settings WHERE key LIKE 'telemetry_%_at'"` then restart node to re-fire
- **wallet_ready** — log in with Particle (or any flow that ends in `POST /auth/particle`) → counter goes 0→1
- **first_capsule_open** — open any non-explorer app from the start menu (Market, Player, Elastos NFT, etc.) → counter goes 0→1
- **first_payment** — view any paid dDRM-protected piece of media (any 2xx exit of `/lit/secure-view`) → counter goes 0→1

After firing once each, stays at 1 forever (idempotent via `settings.telemetry_<event>_at` keys; survives restarts).

### 4. Kill switch
Set `PC2_TELEMETRY_DISABLED=true` in your env before starting the node → all 4 hooks short-circuit + POST endpoint returns `204 {disabled:true}`. `GET /summary` continues to work (returns existing rows, just stops accepting new).

### 5. Privacy check
```bash
sqlite3 pc2-node/data/pc2.db "SELECT key,value FROM settings WHERE key='telemetry_install_id'"
```
Expected: a single UUID v4 (`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx` shape). Never tied to wallet, email, or IP. Never regenerates.
