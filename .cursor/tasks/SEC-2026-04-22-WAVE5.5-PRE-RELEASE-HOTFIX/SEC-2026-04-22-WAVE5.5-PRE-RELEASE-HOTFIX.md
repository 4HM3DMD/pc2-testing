# Task: SEC-2026-04 Wave 5.5 — Pre-release hotfix (A17 + A19)

**Task ID**: SEC-2026-04-22-WAVE5.5-PRE-RELEASE-HOTFIX
**Created**: 2026-04-22
**Status**: InProgress
**Priority**: Critical (v1.2 release-blocking)

## Description

Two release-blocking findings discovered during the post-Wave 5 deep audit:

- **A17** — App-install RCE / arbitrary owner-file exfiltration via
  `POST /api/installed-apps/install-local` + `AppInstallService.installFromLocal`
  + the static `/installed-apps/*` route.
- **A19** — Multer disk-write path traversal: four upload configurations
  interpolate the attacker-controlled `file.originalname` into the on-disk
  filename (`${unique}-${file.originalname}`) before any validation, allowing
  an authenticated user to write arbitrary files anywhere the node process
  has write permission.

Both must close before v1.2 ships. They are the same severity class as A1/A3
which Wave 5 already closed.

## Background

Wave 5 swept terminal/git/backup/voice for RCE and `requireOwner` gaps. The
follow-up audit specifically requested by the user ("do another security audit
and tell me your thoughts on where we are today") extended that sweep to:

1. App-install surface (installed-apps + AppInstallService + static.ts)
2. All Multer disk-storage configurations
3. Scheduler runner (deferred RCE — A18, deferred to Wave 6)
4. CORS substring matching (deferred to Wave 7)
5. `.__puter_gui.json` `endsWith` bypass in `authenticate` (deferred to Wave 7)

A17 + A19 are the items that cannot wait: they let any authenticated wallet
either (a) read the owner mnemonic by sideloading owner files into a fake app
and pulling them via the static route, or (b) write into `~/.ssh`,
`/etc/cron.d`, systemd unit dirs, etc.

## Findings

### A17 — App install RCE / owner-file exfiltration  (Critical)

**Files**
- `pc2-node/src/api/installed-apps.ts:56-140` (4 owner-mutating routes are
  `authenticate`-only, no `requireOwner`).
- `pc2-node/src/services/AppInstallService.ts:276-322` (`installFromLocal`
  copies arbitrary `localDir` into the app dir with no allowlist).
- `pc2-node/src/static.ts:390-456` (`/installed-apps/*` serves the resulting
  files; the existing path-containment check is correct, so this becomes the
  exfil read-path *after* A17 plants the files).

**Attack chain** (any authenticated tethered wallet, no owner privileges):

1. `POST /api/installed-apps/install-local` with body
   ```json
   { "manifest": {"name":"x","title":"x","version":"1.0.0","entry":"index.html"},
     "localDir": "/Users/owner/.../data/wallets" }
   ```
2. `installFromLocal()` runs `resolve(localDir)` (no allowlist), then
   `copyDirRecursive` blasts the entire mnemonic store into
   `data/installed-apps/x/`.
3. Attacker fetches `GET /installed-apps/x/mnemonic.json` (or whatever was
   in `data/wallets`).

**Severity**: Critical — privilege escalation + full mnemonic exfiltration.

### A19 — Multer `originalname` disk-write traversal  (High)

**Files** (4 multer disk-storage configs interpolate `file.originalname` into
the destination filename):

- `pc2-node/src/api/index.ts:1199-1227` — general `/batch` upload AND the
  backup restore upload.
- `pc2-node/src/api/setup.ts:54-70` — restore-mnemonic backup upload.
- `pc2-node/src/api/media.ts:1454-1466` — media encode upload.

**Why exploitable**: `path.join('/tmp/uploads',
'1745-abc-../../../etc/cron.d/evil')` normalizes to `/etc/cron.d/evil`. The
unique prefix is its own segment that `..` cancels. Multer writes the file
to disk **before** any route-level validator runs, so route-level filename
checks (e.g. the Wave 5 `isValidBackupFilename` in the restore handler) do
not protect the disk-write path.

**Severity**: High — arbitrary file write to anywhere the node has perms.

## Implementation Plan

### A17 fix

- [ ] **`pc2-node/src/api/installed-apps.ts`**
  - Import `requireOwner` from `./middleware.js`.
  - Add `requireOwner` to:
    - `POST /install`
    - `POST /install-local`
    - `POST /update`
    - `DELETE /:name`
  - Keep `GET /` and `GET /:name` as `authenticate`-only (read-only).

- [ ] **`pc2-node/src/services/AppInstallService.ts`**
  - In the constructor, compute `this.devAppsRoot = resolve(dataDir, 'dev-apps')`
    and create the dir on first use.
  - In `installFromLocal`, after `resolve(localDir)`:
    - Reject if the resolved path does not start with `this.devAppsRoot + sep`
      (and is not equal to `this.devAppsRoot`).
    - Reject if the resolved path equals or is inside `this.appsDir`
      (prevent self-targeting loops).
  - Defense-in-depth on top of the route-level `requireOwner` gate.

- [ ] **`pc2-node/src/static.ts`** — no change. The existing
  `filePath.startsWith(appDir + sep)` check (line 407) already prevents
  reads outside the app directory. A17 is closed at the install layer.

### A19 fix

- [ ] **`pc2-node/src/api/index.ts`** (two configs)
  - Replace both
    `cb(null, '${unique}-${file.originalname}')`
    with
    `cb(null, '${unique}.upload')`.
  - For `restoreUpload`, also add a `fileFilter` that requires
    `req.file.originalname` to match `/^[A-Za-z0-9_.-]+\.tar\.gz$/`.

- [ ] **`pc2-node/src/api/setup.ts`**
  - Replace the disk filename with `'${unique}.tar.gz'` (the existing
    `fileFilter` already requires `.tar.gz`).
  - Tighten the `fileFilter` to the same strict regex
    `/^[A-Za-z0-9_.-]+\.tar\.gz$/` so a name like `../../foo.tar.gz` is
    rejected even though the disk filename is now safe.

- [ ] **`pc2-node/src/api/media.ts`**
  - Replace the disk filename with `'${unique}.upload'`. Multer still
    preserves `req.file.originalname` for handlers that want to display it.

### Smoke tests

- [ ] **`pc2-node/scripts/wave5-smoke.sh`** — append A17 + A19 cases:
  - Tethered wallet `POST /api/installed-apps/install-local` → 403.
  - Owner `POST /api/installed-apps/install-local` with
    `localDir: '../../etc'` → 400.
  - `POST /api/backups/restore` with `filename="../../etc/passwd.tar.gz"` →
    on-disk file lands under the upload tmp dir (no `/etc/passwd.tar.gz` is
    created) and the route returns 400.

### Documentation

- [ ] Update `docs/handover/SEC_2026_04_21_AUDIT_DISPOSITION.md`:
  - Add A17 + A19 to the "Hard-fixed" table once these commits land.
  - Note Wave 5.5 was inserted between Wave 5 and the v1.2 release.
  - Move A18 (scheduler deferred RCE) and the CORS substring + `.__puter_gui.json`
    `endsWith` bypass into the Wave 6/Wave 7 lists explicitly.

## Acceptance Criteria

- All four owner-mutating `installed-apps` routes return 403 for tethered wallets.
- `installFromLocal` rejects any `localDir` outside `data/dev-apps/`.
- Static route `/installed-apps/*` cannot be used to read files placed there
  by an attacker (because A17 prevents the placement in the first place).
- All four multer disk-storage configs produce a sanitized on-disk filename
  that ignores `file.originalname`.
- A path-traversal `originalname` in a backup-restore upload is rejected by
  the `fileFilter` and never lands outside the upload tmp dir.
- TypeScript builds clean.
- All Wave 5 + Wave 5.5 smoke tests pass against a fresh node.
