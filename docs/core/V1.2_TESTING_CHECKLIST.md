# v1.2 Manual Testing Checklist

> **Purpose:** Concrete click-through smoke list for the founder before tagging v1.2.0. Complements RG3 (the 26-case `wave5-smoke.sh` matrix, which is API-level) with eyes-on-the-UI validation of every bundled app.
> **Scope:** Owner-mode session, fresh node restart, both wallet-login flows.
> **Time budget:** ~45 minutes for the full pass.
> **Created:** 2026-04-23

## Pre-flight (5 min)

- [ ] Restart node cleanly (`npm run dev` from `pc2-node/`); confirm the start banner shows v1.2.x
- [ ] Tail the log for the first 60 seconds, confirm zero `WARN`/`ERROR` (other than well-known ones — the kill-switch warning if `siweRequired=false` is expected)
- [ ] Open `http://localhost:4200` in a fresh browser profile (no cached cookies)
- [ ] Confirm desktop loads, taskbar shows all 7 apps (creator, market, NFT, glide, player, viewer, supernode-manager)
- [ ] Confirm scrollbar styling matches the dark Elacity palette (no native chrome scrollbars)

If any pre-flight fails: STOP, file an issue, do not proceed.

---

## Login flows (10 min)

### A. Wallet-based login (SIWE)

- [ ] Click "Sign in with wallet" → MetaMask/Particle popup appears
- [ ] Sign the EIP-4361 message → land on the desktop with your address shown in the taskbar
- [ ] Refresh the page → stay logged in (session persists)
- [ ] Sign out → SIWE message is presented again on next attempt

### B. Email / social login (Particle Auth)

- [ ] Click "Sign in with email" → Particle popup appears for OTP
- [ ] Complete OTP → on first transaction attempt, the in-built Particle sign popup appears (this is correct, not the SIWE flow)
- [ ] Approve a no-op signature (e.g. open Creator and click "Save Draft") → no errors
- [ ] Refresh → stay logged in

## Per-app smoke (20 min — ~3 min per app)

### 1. Elacity Creator

- [ ] Open from start menu → loads inside the Elacity dark palette (no purple residue from the v1.1 theme)
- [ ] Browse to "Mint a draft" → form fields render correctly
- [ ] Upload a small test file (e.g. a 10 KB PDF) → file appears in the upload list
- [ ] Save draft → no console errors; `mint-draft-saved` postMessage event fires (visible in DevTools "Network → WS")
- [ ] Cancel draft → `mint-close-creator` postMessage fires

### 2. Elacity Market

- [ ] Open from start menu → loads with dark palette
- [ ] Browse a listing → thumbnails load; filters work
- [ ] Open a detail page for any asset → metadata renders
- [ ] Click "Buy" (don't complete the tx — just confirm the wallet popup appears with the correct amount)

### 3. Elastos NFT (`elastos-nft`)

- [ ] Open from start menu → loads
- [ ] Browse a collection → grid renders
- [ ] Click a token → detail view loads with correct ESC NFT metadata
- [ ] Confirm chain switch prompt (if triggered) goes through correctly

### 4. Glide Finance (`glide-finance`)

- [ ] Open from start menu → loads
- [ ] Connect wallet inside Glide → wallet bridge correctly forwards the signing request
- [ ] Browse a pool → liquidity numbers populate (depends on ESC RPC)
- [ ] Confirm no console errors in the Glide iframe (DevTools → Console, scoped to the iframe)

### 5. Elacity Player (DRM media — the just-rebranded one)

- [ ] Open from start menu → loads with the Elacity dark palette (no purple residue)
- [ ] Open a sample DRM video asset (use one you've previously minted on dev) → play
- [ ] Confirm the player controls render in Elacity blue (`#3b82f6`), not the old indigo
- [ ] Confirm the spinner shows the new Elacity dark border colour
- [ ] Trigger the error state (e.g. open a non-existent asset) → confirm the errorBox uses `#1a1a1a` background, not `#1e1b2e` purple-tinted

### 6. Elacity Viewer (`ddrm-viewer` — non-media)

- [ ] Open a `.ddrm.json` asset (image, PDF, code) → renders inside the WASM viewer
- [ ] Hover over an EPUB nav button or size button → confirm hover state uses Elacity blue tint, not purple
- [ ] Confirm CSS variables (`--accent-soft`) are applied correctly (DevTools → Computed)

### 7. Supernode Manager

- [ ] Open from start menu → loads
- [ ] List supernodes → returns the current supernode list
- [ ] Inspect any supernode entry → details render
- [ ] No console errors

## Cross-cutting flows (5 min)

### Wallet bridge

- [ ] Inside Creator: trigger a `wallet:read` operation (e.g. address display) → no popup, just a result
- [ ] Inside Glide or Market: trigger a `wallet:sign` operation → exactly one wallet popup
- [ ] Confirm `network:rpc` calls (block number, etc) are cached (open the same view twice, see only one network request in DevTools)

### File capability URLs (A16 — Wave 6 Part 2)

- [ ] Open a thumbnail in any app → confirm the URL has a signature (`&sig=...&exp=...`)
- [ ] Manually edit the signature in the URL bar (change one character) → confirm the response is `403` or `400`
- [ ] Wait until the `exp` timestamp passes (or set a low TTL via the env override) → confirm the URL stops working

### Backup / restore

- [ ] Open Settings → Backup → click "Create backup"
- [ ] Confirm `.tar.gz` (or whatever the backup format is) downloads
- [ ] On a separate clean node (or a renamed `data/` folder), restore the backup
- [ ] Confirm wallet, installed apps, and settings all restored
- [ ] Sign in again → previous data accessible

## Security validations (5 min — sanity-only; full coverage is in the wave5-smoke.sh)

- [ ] Try to install an app from a path outside `data/test-apps/` or `data/dev-apps/` (e.g. `data/wallets/`) via the API → confirm rejected with the SEC-A17 allowlist error
- [ ] Try to access `/file?uid=...` without a signature (or with a bad one) → confirm rejected (A16 verification)
- [ ] Try `POST /api/install-ollama` without owner session → confirm `requireOwner` rejection (A7)
- [ ] Try to install ollama with a hash mismatch (modify `OLLAMA_INSTALL_SH_SHA256` env to a wrong value) → confirm hash-mismatch rejection (A7)
- [ ] Try a fetch via `/api/http-client` to a redirect that points to localhost → confirm DNS-rebind protection blocks (A11)
