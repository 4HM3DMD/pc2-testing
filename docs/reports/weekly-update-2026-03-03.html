What We Shipped in v1.1.0

1) Four-Tier Stealth Transport Cascade 🛡️
ElastOS nodes now connect to the network through a four-tier transport cascade that automatically finds the best connection method — and falls back through increasingly stealthy options if your network tries to block it:
  1. WireGuard — Fast, encrypted UDP tunnel. Works on most networks.
  2. AmneziaWG — Same speed, but disguised so Deep Packet Inspection (DPI) firewalls can't tell it's a VPN. Built for countries that block standard VPN traffic.
  3. VLESS Reality — Wraps your connection inside what looks like a normal HTTPS visit to microsoft.com. Even if all UDP is blocked, this TCP-based tunnel gets through.
  4. ActiveProxy — Last resort relay through the supernode. Always works, no matter what.
The system is fully automatic: if your ISP or government firewall blocks one layer, the node detects it within seconds and moves to the next. It also periodically retries faster tiers so it moves back up when possible. All four tiers are tested and working on both macOS and NVIDIA Jetson, with sing-box 1.13.0 pinned across all nodes for stability. Why it matters: Your personal cloud should be reachable from anywhere — whether you're on a coffee shop WiFi, a corporate network, or behind a national firewall. This is the same principle as Tor or Signal, but built directly into your cloud's networking layer.
2) Desktop Launcher: Version Display & One-Click Updates
The ElastOS Desktop Launcher (v1.1.0) now shows the actual version of your installed PC2 node instead of a hardcoded number. It checks GitHub for new releases in the background — and when an update is available, a green "Update" button appears right next to the version. One click pulls the latest code, installs dependencies, rebuilds, and restarts your node. No terminal needed. Why it matters: The goal is zero-friction sovereign computing. A user who downloaded the launcher should never have to open a terminal to stay up to date. This brings the ElastOS update experience closer to what people expect from consumer apps.
3) Desktop UI Upgrades
The ElastOS desktop now supports a full-width top bar with the Elastos logo on the left, and search, wallet, profile, and a clock on the right. Users can switch between the original floating toolbar and the new full top bar in Settings under "Desktop Layout." The file explorer also received polish: larger default windows, proper file timestamps (no more "just now" on every file), refined list view colors, and a background color picker for desktop wallpapers. Mobile received fixes too — the taskbar now renders correctly on phones with proper z-index layering and forced toolbar mode. Why it matters: A polished, familiar desktop experience lowers the barrier to entry, which is critical for a personal cloud OS competing for daily use.
4) Voice AI Pipeline
ElastOS now has a voice AI pipeline with speech-to-text input, context-aware processing, and resilient Ollama integration. The AI can access your file system and application state through a new Context API, meaning your personal AI assistant understands what you're working on. Why it matters: Voice interaction is the natural interface for a personal cloud. Having AI that understands your files and context — running privately on your own hardware — is a capability no centralized cloud offers.
5) ARM Installer Hardening
A full overhaul of the ARM install script ensures that Jetson and Raspberry Pi users get a working node on the first try. The fixes are specific and battle-tested — every one was discovered by real community members deploying on real hardware:
  • Go version auto-detection — if the system Go is too old (Jetson ships with Go 1.18), the script downloads Go 1.24 automatically to build AmneziaWG
  • AmneziaWG built from source — uses git clone + make instead of go install, which was pulling old tagged versions that couldn't handle AWG 2.0 config parameters
  • sing-box 1.13.0 pinned — version 1.11.0 had bugs in UDP-over-TCP multiplexing that caused VLESS Reality tunnels to drop after 5 seconds
  • sudo user detection fixed — running sudo bash install-arm.sh no longer creates a duplicate PC2 install under /root/
  • Jetson power mode optimization — auto-detects available power modes and sets the highest (up to 25W MAXN_SUPER on Orin Nano)
  • Rogue install cleanup — detects and removes accidental /root/pc2.net installations from previous buggy script runs
Why it matters: Every failed install is a lost user. These fixes target the exact failure modes reported by community members. The path from "fresh Ubuntu on a Jetson" to "running ElastOS with stealth networking" is now a single command.
6) WireGuard Networking Improvements
WireGuard reconnection was improved with exponential backoff starting at 15 seconds instead of a flat 60-second retry. WireGuard is now preferred over the Active Proxy fallback on reconnect, and detection was fixed for restricted environments like PM2 and systemd where the system PATH doesn't include standard binary locations. Gateway keep-alive was also hardened. Why it matters: Faster reconnection means less downtime when network conditions change. For users running ElastOS on a Jetson at home behind a consumer router, this translates to a more reliable always-on experience.
7) Upload Reliability
File uploads now show accurate 100% progress and verify file size against IPFS after upload. Truncated uploads on large files are detected and reported to the user instead of silently succeeding with corrupted data. Why it matters: Your personal cloud is only as trustworthy as its storage. Users uploading large video files or backups need confidence that what they uploaded is what got stored.
8) Security & Code Quality
  • Structured logging — all console.log calls across the backend replaced with a module-aware logger ([PC2:static], [PC2:ipfs], etc.) gated by LOG_LEVEL. No more debug noise in production.
  • Credential rotation — supernode SSH passwords rotated and removed from documentation; references now point to password manager
  • Development artifacts excluded — .gitignore updated to prevent SDK clones and test files from being committed

Bug Fixes & Polish

  • AV1/Firefox video playback — proper error handling and format support for next-gen video codecs
  • Search modal padding — even spacing above and below the search input, icon vertically aligned
  • Profile dropdown — disabled items now transparent in light mode instead of white blocks
  • Loading screen — now reads "Personal Cloud Compute"

Elacity dDRM & dApp Store: Planning Complete

Alongside the v1.1.0 release, we completed deep research into the Elacity SDK and produced a comprehensive architecture plan for a decentralized app store and media marketplace built on top of PC2. The vision: users browse an app store inside their ElastOS desktop, install apps from IPFS, and creators can monetize content using Elacity's tokenized digital rights management (dDRM) system — all without a centralized gatekeeper. Key planning milestones:
  • Elacity SDK deep-dive — full source audit of all seven @elacity-js/* packages (contracts, API, media packager, player, adapters)
  • dApp Store architecture — app manifest format, IPFS-backed registry, iframe sandboxing with postMessage wallet bridge, SQLite install tracking
  • App Factory concept — a future feature where developers can package and publish apps directly from their own PC2 node
  • ERC-8004 research — evaluated the draft "Trustless Agents" standard for AI agent registry and reputation; mapped to PC2's node identity system for Phase 2-3 integration
  • V1→V2 bridge strategy — every component designed with explicit migration paths to the capsule-based runtime
This work is now the first priority on the post-v1.1.0 roadmap, tracked in a dedicated feature/elacity-ddrm-marketplace branch. Why it matters: A personal cloud without apps is a hard drive with a nice UI. The app store turns ElastOS into a platform — one where developers ship to users directly, without Apple or Google in the middle, and where digital content has real ownership through on-chain DRM.

Runtime & Capsule Architecture: V2 Foundations

While v1.1 shipped on the product side, parallel work on the ElastOS Rust runtime reached a significant milestone. A working P2P chat system was built from scratch using five capsules — a localhost provider, shell, DID identity provider, peer networking provider, and the chat application itself — all running on the new capability-secured runtime. This validates the core architectural model: a minimal trusted runtime (pure Rust, ~10 crates) that enforces sandboxes, validates Ed25519 capability tokens, and routes provider protocols — while all higher-level functionality runs in isolated capsules. Each capsule carries its own execution world: microVM capsules run a full Linux environment, WASM capsules run on a thin WASI layer, and application capsules interact through capability tokens that grant exactly the permissions needed — nothing more. The three-layer model is crystallizing: PC2 OS (host hardware and kernel), ElastOS Carrier (the trust plane — capability enforcement, capsule lifecycle, provider routing, audit trail), and AppCapsule Runtime (per-capsule execution with its own isolated world). The shell capsule — today a simple auto-grant loop — is designed to evolve into an intelligent orchestrator, where permission decisions become conversations rather than popups, and AI agents operate under the same security model as human users. Architectural discussions also advanced URI namespace design, aligning with W3C DID conventions so that all Elastos ecosystem services route through a unified elastos:// scheme — peer networking, identity, AI, and content addressing all under one coherent namespace. This keeps the runtime frozen and timeless while the ecosystem of providers and applications evolves independently. Why it matters: This is the bridge from ElastOS V1 (a working product) to V2 (a capability-secured runtime where every app, agent, and service is cryptographically sandboxed). The security model — where AI agents get exactly the authority they need, audited and revocable — is unique in the industry. No other system lets AI operate inside a personal cloud with this level of granular, cryptographic trust.
